# Правила заполнения полей CRM

## ТегиКЦ (UF_CRM_1706806189)

Тип медицинского запроса. Поле multiple=Y — можно указать несколько значений (массив).

**Источник истины — оператор КЦ.** Авторазбор (LLM) только подстраховывает, не угадывает.

### Когда авторазбор МОЖЕТ писать ТегиКЦ

1. Поле **пустое**: нет значения / `False` / пустой массив. В PBI пустое часто видно как «не выбрано» — это тоже пусто.
2. Тег **очевиден из разговора** (расшифровка / чат / комментарии): прямо названы онколог, гематолог, ревматолог, второе мнение, выезд, лапаро/торакоцентез и т.п.

### Когда авторазбор НЕ пишет ТегиКЦ

- Поле **уже заполнено человеком** — не перезаписывать.
- **Сомнение** (неясно направление, несколько равноправных вариантов, нет текста разговора) — **не писать** и не угадывать. Допустимо только явно поставить `Другие` (1894), если из разговора ясно, что запрос есть, но ни один узкий тег не подходит.
- Нет коммуникации / пустой UF-транскрипт при коротком касании — не выводить тег «из воздуха».

Неверный уверенный тег хуже пустого поля: BI будет показывать ложный спрос.

## Вариация приема (UF_CRM_1768816592560)

Заполнять ВСЕГДА. Никогда не оставлять пустым. Формат взаимодействия.

| Значение | Когда ставить |
|---|---|
| Очный прием | Пациент хочет записаться на приём к врачу |
| Дистанционный прием | Пациент хочет онлайн-консультацию |
| Прямая продажа | Пациент запрашивает препарат (покупка) |
| Запрос на ХТ | Запрос на химиотерапию |
| Выезд онколога на дом | Запрос выездной консультации |

Типичная ошибка: "Дистанционный прием" вместо "Прямая продажа" когда пациент покупает препарат.

## Название препарата (UF_CRM_1748956354216)

Если в тексте упомянут препарат → поле НЕ может быть "Не применимо" (F01).

Известные искажения в расшифровках (R07):
- бралаксан / абраксан 100 → Абраксан
- энхерта / энхерту → Энхерту
- кселода / кселоду → Кселода
- доксорубицин → Доксорубицин
- паклитаксел → Паклитаксел
- датровэй / датопотамаб / датопотамаб дерукстекан → Датровей

Если препарат упомянут, но отсутствует в справочнике → написать в поле Задача: `ДЕФИЦИТ СПРАВОЧНИКА: [название]`

Известные дефициты справочника:
- Абраксан 100мг (нет в наличии, под заказ 5-8 дней, ~101 000 руб.)

Добавленные в enum препараты (с ID):
- Датровей → enum ID=2640 (добавлен 20.05.2026; МНН: Датопотамаб дерукстекан)

## Статус детальный (UF_CRM_1747754997445)

| Статус | Когда ставить |
|---|---|
| Связаться с пациентом | Ждём ответа клиента / договорились о дате / пациент написал но не получил ответа / пациент сказал "подумаю" |
| Направить смету | Пациент запрашивает стоимость лечения |
| Дорого | Клиент ЯВНО сказал "дорого" |
| Нет услуги | Оператор ЯВНО сообщил что услуга отсутствует |
| Пациент не отвечает | Несколько попыток без ответа (F03) |
| Отказ пациента | Только при ЯВНОМ отказе пациента (F03) |

Типичные ошибки:
- "Ожидаем ответа" когда в задаче ничего нет про обратный контакт
- "Отправить смету" когда смета уже была отправлена ранее
- "Дорого" когда клиент не говорил о цене
- "Отказ пациента" когда пациент просто не отвечает

## Причина инф. обращения (UF_CRM_1738678828702)

Заполнять ТОЛЬКО для лидов со стадией "Информационное сообщение".
Поле multiple=Y.

Верифицировать по содержанию разговора. Возможные значения:
- Интересовались адресом и как добраться
- Готовность анализов и обследований
- Интересовались куда направить документы
- Бухгалтерские письма
- Интересовался способами оплаты
- Ошибка стадирования (пациент реально мог бы записаться — ставить статус "ошибка стадирования")

Если из расшифровки ясно, что стадия "Информационное сообщение" поставлена неверно и пациент мог бы записаться → отметить как "ошибка стадирования".

## Задача по лиду (UF_CRM_1747750972275)

При незакрытом диалоге — поле НЕ может быть пустым.

Формат: конкретное действие + срок + зачем.

Примеры:
- `Перезвонить 25.05, уточнить решение о начале лечения`
- `Отправить смету на Энхерту сегодня`
- `Связаться через Telegram, пациент не берёт трубку`
- `Передать вопрос по анализам врачу Шурниковой, ответ — завтра`
- `ДЕФИЦИТ СПРАВОЧНИКА: Абраксан 100мг — уточнить наличие у поставщика`

## Нативный протокол `[FEEDBACK]`

Вместо формы администратор/врач пишет несогласие ОДНИМ сообщением прямо в `chat31598`:

```
[FEEDBACK][лид:НОМЕР]
было: <что поставил AI>
верно: <как правильно>
причина: <кратко почему>
```

На каждом плановом прогоне Claude:
1. читает `chat31598` через `im.dialog.messages.get`;
2. парсит сообщения с якорем `[FEEDBACK]` (извлекает `lead_id`, было/верно/причина, `fb_id`);
3. классифицирует несогласие: тип **O** (разовая фактическая ошибка → «учтено», правило не меняется)
   vs тип **R** (системная ошибка логики → меняем правило);
4. для типа R формулирует изменение как **было → стало** (дословный diff блока правила);
5. проводит его через гейт ДВУХ утверждающих ролей — старший администратор (`user_id 11822`) и
   исполнительный директор (`user_id 8`); правило применяется только после ДВУХ `УТВ` от этих
   РАЗНЫХ user_id.

**Полный детерминированный протокол — Шаг 8 «Обработка обратной связи и дообучение» в `SKILL.md`.**

Канон правил для записи — `_память_claude/правила_анализа_лидов.md`
(краткое зеркало — `.auto-memory/feedback_lead_analysis_rules.md`).
